## Ключевые технические решения

### Модель данных (`models.py`)
Таблица `cameras`: `id, name, nvr_host, rtsp_port, username, password, channel, stream_type ('main'|'sub'), enabled, created_at, updated_at`. Полный RTSP URL в БД не хранится — генерируется из параметров.

### Dahua URL (`dahua.py`)
`rtsp://user:pass@host:554/cam/realmonitor?channel=N&subtype=0|1`. Логин/пароль URL-кодируются (`urllib.parse.quote`, пароль содержит спецсимволы). Функция `masked_url()` заменяет пароль на `***` для логов.

### RTSPReader (`reader.py`) — независим от FastAPI и AI
- **Подключение**: сначала `ffprobe` (JSON: codec_name, width, height, avg_frame_rate) с subprocess-timeout — даёт метаданные и размер кадра; затем subprocess FFmpeg:
  `ffmpeg -rtsp_transport tcp -timeout <мкс> -fflags nobuffer -flags low_delay -i <url> -an -sn -dn -f rawvideo -pix_fmt bgr24 pipe:1`
- Кадры — numpy BGR (готовы для будущего AI). Чтение точными блоками `w*h*3` из stdout.
- **Фоновый поток** + авто-реконнект с exponential backoff **1,2,4,8,16,30,30… сек** (сброс после первого успешного кадра). Статусы: `CONNECTING → ONLINE → RECONNECTING → ONLINE / OFFLINE / ERROR`.
- **Watchdog**: нет кадров N секунд → соединение считается потерянным → реконнект (защита от зависаний TCP).
- **FrameBuffer**: `deque(maxlen=2)` + Condition — «drop old, keep latest», ориентация на актуальный кадр. `wait_for_new(seq, timeout)` для потребителей.
- Runtime-статистика в памяти: `last_frame_at, current_fps` (EMA), `resolution, codec, reconnect_count`.
- API класса: `connect(), read(), disconnect(), reconnect(), is_alive()` + `start()/stop()`. stderr FFmpeg сливается в отдельном потоке (кольцевой буфер, пароль маскируется). Отсутствие FFmpeg → статус ERROR с понятным сообщением, приложение продолжает работать.
- Завершение: stop_event + terminate/kill процесса + join — корректный shutdown приложения.

### ReaderManager (`manager.py`)
Словарь `camera_id → RTSPReader` под lock. `startup_from_db()` (при старте приложения читает все enabled-камеры и запускает ридеры), `start/stop/restart/get/status/stop_all`. Хранится в `app.state`.

### API (`api/cameras.py`) — порядок маршрутов: `/test` до `/{id}`
- `GET /api/cameras` — список + live-статус каждой камеры (для автообновления UI)
- `GET /api/cameras/{id}`; `POST /api/cameras` (ридер стартует, если enabled); `PUT /api/cameras/{id}` (пароль пустой/отсутствует = не менять; при изменении параметров — рестарт ридера); `DELETE /api/cameras/{id}`
- `POST /api/cameras/{id}/test` и `POST /api/cameras/test` (параметры без сохранения — для формы добавления). Реально запускает ffprobe с timeout; успех: `✓ codec/resolution/fps`, ошибка: generic «Unable to connect to RTSP stream» без пароля и URL
- `GET /api/cameras/{id}/status` — runtime-информация
- `GET /api/cameras/{id}/stream` — multipart MJPEG (`StreamingResponse`, sync-генератор → threadpool, не блокирует event loop). JPEG через `cv2.imencode` (качество ~70), ограничение `PREVIEW_FPS` (по умолчанию 10), при отсутствии кадров >2 сек — заглушка «NO SIGNAL». Плейсхолдер-кадр генерируется OpenCV.

### Безопасность
Пароль никогда не возвращается API (Pydantic response-модель без password + `has_password`), не логируется (маскированный URL), не попадает в HTML/JS и тексты ошибок.

### Web UI (русский, ванильный JS + Jinja2, тёмная простая тема)
- **index.html**: заголовок «Camera Monitor», список камер (● имя, цветной статус ONLINE/CONNECTING/RECONNECTING/OFFLINE/ERROR, кнопки Открыть/Изменить/Удалить), кнопка «+ Добавить камеру», автообновление статусов каждые 3 сек. Модальная форма: Name, NVR IP, RTSP Port, Username, Password, Channel, Stream (main/sub) + «Test connection» (результат: ✓ Connected + Resolution/Codec/FPS или ✕ Connection failed) + «Сохранить». При редактировании поле пароля — «оставьте пустым, чтобы не менять».
- **camera.html**: `<img src="/api/cameras/{id}/stream">`, название, панель live-статуса (fps, разрешение, кодек, реконнекты, последний кадр), обновление каждые 2 сек, кнопка назад.

### requirements.txt
`fastapi`, `uvicorn[standard]`, `sqlalchemy>=2.0`, `pydantic>=2`, `pydantic-settings`, `opencv-python-headless`, `jinja2`.

### Конфигурация
`.env.example` (и `.env` с теми же значениями, чтобы `python main.py` работал сразу): APP_HOST=0.0.0.0, APP_PORT=8000, DATABASE_URL=sqlite:///./data/app.db, RTSP_CONNECT_TIMEOUT=10, RTSP_RECONNECT_MAX_DELAY=30, DEFAULT_RTSP_PORT=554 + доп.: FFMPEG_PATH (пусто = автоопределение), PREVIEW_FPS=10, FRAME_BUFFER_SIZE=2.

## Верификация на реальном NVR (этап «сначала одна камера»)

1. После установки FFmpeg — ffprobe-прозвон каналов 1–16 (`subtype=0`): найти активные каналы NVR.
2. Запустить приложение в фоне (`venv/Scripts/python main.py`), проверить `curl http://localhost:8000/api/cameras`.
3. Добавить первую камеру через `POST /api/cameras` (канал 1, main) → `POST /api/cameras/{id}/test` → убедиться в успехе (codec/resolution/fps реального потока) → `GET .../status` = ONLINE → `GET .../stream` = валидный multipart-JPEG (проверить байты SOI-маркеров).
4. Добавить остальные активные каналы (main, имена «Канал N»), убедиться, что все ридеры ONLINE.
5. Проверка реконнекта: убить процессы ffmpeg (taskkill) → статусы RECONNECTING → снова ONLINE без перезапуска приложения.
6. Браузерная проверка через browser-навык: главная страница, добавление/редактирование, живое превью камеры, скриншоты для подтверждения.
7. Проверить, что пароль не встречается ни в API-ответах, ни в логах.
